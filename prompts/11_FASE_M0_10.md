## 2. Invariants Arsitektur & Keamanan M0 yang Mutlak Dipatuhi

1. **Satu Proses Go & Sembilan Schema PostgreSQL Terpisah**:
   - Tetap satu binary Go modular monolith dan satu instance PostgreSQL dengan sembilan database role/pool terisolasi (maksimal 4 koneksi per owner, total budget 36).
   - Dilarang membuat microservices terpisah, dilarang HTTP loopback palsu antar-modul, dan dilarang membuat *shared business service* atau *shared repository* yang mengaburkan batas domain M9.
   - Dilarang keras melakukan JOIN lintas skema antara `notify_audit` dengan `identity`, `catalog`, `intake`, atau skema lainnya. Integrasi data bersumber murni dari event outbox/inbox durable atau DTO publik terpercaya.
2. **Larangan Mutlak Pengiriman Eksternal Nyata & Deterministic Notification Sink**:
   - Dilarang keras mengirim notifikasi Telegram bot nyata, webhook internet riil, atau email SMTP produksi (*no real external sends*).
   - Seluruh pengiriman saluran menggunakan deterministic synthetic notification sink (`channel = 'SINK'`) yang mensimulasikan penerimaan pesan, status pengiriman (`STORED`, `SINK_ACCEPTED`, `FAILED`, `DEAD_LETTER`), pencatatan jumlah percobaan (*attempts*), dan pencatatan error code tanpa efek samping jaringan eksternal.
3. **Telegram Binding Terverifikasi, Penolakan Salah Scope & Sensor Secret (AC21)**:
   - Pengikatan saluran Telegram (`POST /api/v1/notifications/telegram-bindings`) mewajibkan verifikasi scope yang ketat:
     - Chat ID milik publik/tamu dilarang keras diikatkan ke scope organisasi internal OPD atau tiket rahasia staf.
     - Staf dari OPD A dilarang mengikatkan chat ID ke organisasi OPD B yang berada di luar kewenangannya.
     - Pengikatan dengan scope yang tidak sah, organisasi tidak terdaftar, atau verification code invalid **WAJIB DITOLAK TEGAS** (HTTP `400 INVALID_REQUEST`, `403 FORBIDDEN`, atau `422 VALIDATION_FAILED`).
   - **Penyensoran Kredensial / Sensor Secret (AC21)**:
     - Kredensial rahasia bot token Telegram, verification code, maupun referensi chat pribadi **DILARANG KERAS** muncul dalam bentuk teks mentah (*plaintext*) pada respons API, catatan audit log, pesan error HTTP, maupun log konsol.
     - Respons API dan log wajib menyensor nilai rahasia (contoh: format mask `TG-***`, `1234****`, atau masked token).
   - **Visibilitas Kegagalan Delivery & Pelacakan Retry (AC21)**:
     - Status kegagalan pengiriman pada job delivery (`delivery_jobs`) dan riwayat percobaan (*retry attempts*) wajib tercatat durable dan dapat dipantau oleh operator/admin yang berhak tanpa membocorkan kredensial rahasia.
   - **Pencabutan Seketika (Revoke Binding - AC21)**:
     - Endpoint pencabutan `POST /api/v1/notifications/telegram-bindings/{id}/revoke` seketika menonaktifkan binding (`revoked_at = now()`) dan mencegah seluruh pengiriman pesan di masa mendatang ke chat ref terkait.
4. **Laporan, Analitik & Ekspor Ber-ACL Ketat dengan Dynamic Revocation Gate (AC23)**:
   - Endpoint laporan `GET /api/v1/reports` dan ekspor `POST /api/v1/reports/exports` mewajibkan izin eksplisit `report.read` dan `report.export` (dimiliki oleh peran `AUDITOR`, `COORDINATOR`, dan `LEADERSHIP`).
   - Penolakan Konfigurasi Admin Implisit: Pengguna dengan peran admin platform atau konfigurasi master (seperti `ADMIN_OPD`) yang tidak memiliki permission `report.read`/`report.export` **DILARANG** secara otomatis membaca laporan tiket atau mengekspor data operasional.
   - **Dynamic Revocation Gate (AC23)**:
     - Izin akses laporan dan izin unduh berkas ekspor (`GET /api/v1/reports/exports/{id}/download`) **WAJIB DIPERIKSA ULANG SECARA LANGSUNG (*live check*)** terhadap status sesi aktor saat request berlangsung (`live_revocation_required: true`).
     - Saat hak `report.read` atau `report.export` seorang pengguna dicabut, peran diubah, atau pengguna melakukan logout:
       - Query laporan `GET /api/v1/reports` seketika mengembalikan HTTP `401 Unauthorized` atau `403 Forbidden`.
       - Permintaan ekspor baru seketika ditolak (HTTP 401/403).
       - Permintaan unduh terhadap file ekspor yang sebelumnya pernah dibuat oleh pengguna tersebut **SEKETIKA DITOLAK (HTTP 401/403)**, dilarang menyajikan file cache dari storage, dan dilarang membocorkan *count*, *snippet*, maupun agregat ringkasan data terlarang!
5. **Sanitasi Formula CSV & Masking PII pada File Ekspor**:
   - Seluruh data yang diekspor ke dalam format CSV wajib melalui sanitasi formula (*CSV formula injection prevention*): setiap sel teks yang diawali dengan karakter formula berbahaya (`=`, `+`, `-`, `@`, tab `\t`, atau carriage return `\r`) wajib diprefix secara otomatis dengan tanda kutip tunggal (`'`).
   - Data sensitif seperti token capability tamu, nomor kontak pribadi tidak terverifikasi, dan catatan internal teknisi wajib dimasking atau disaring keluar dari file ekspor publik/auditor.
6. **Dasbor Analitik Berdenominator Jujur & Bebas Perankingan Naif**:
   - Seluruh metrik laporan pada `GET /api/v1/reports` wajib menyajikan metadata lengkap: `as_of` (waktu cut-off data), `watermark` batas event, `timezone: "Asia/Jakarta"`, `policy_version`, `denominator` (jumlah total populasi dasar), `count` (jumlah kasus terhitung), dan `measure` (`SLA`, `BACKLOG`, `TECHNICIAN`, `VISITOR_SESSIONS`).
   - **Larangan Menyembunyikan Cohort Breached**: Tiket terbuka yang telah melanggar batas waktu SLA (*breached*) wajib tetap ditampilkan dalam cohort perhitungan, dilarang disembunyikan untuk mempercantik angka kepatuhan.
   - **Larangan Perankingan Teknisi Naif**: Kinerja teknisi tidak boleh diukur atau diranking semata-mata dari total kuantitas tiket yang diselesaikan tanpa mempertimbangkan kompleksitas, tiket reopen, atau status jeda waktu (*paused*).
   - **Agregat Pengunjung Portal Bersih**: Data sesi pengunjung portal pada tabel `notify_audit.visitor_aggregates` wajib menerapkan filter bot berversi (`bot_policy_version`), dan **DILARANG** disebut atau diklaim sebagai "jumlah warga unik" (sesuai blueprint Seksi 11).
7. **Jejak Audit Append-Only & Immutability Ledger (M9)**:
   - Seluruh catatan audit pada tabel `notify_audit.audit_entries` dan `notify_audit.audit_intents` bersifat kekal (*append-only* dan *immutable*).
   - Dilarang menyediakan endpoint atau kueri SQL untuk melakukan UPDATE atau DELETE terhadap rekaman audit.
   - Akses pembacaan audit `GET /api/v1/audit` dibatasi ketat hanya untuk aktor dengan permission `audit.read` (peran `AUDITOR`). Pengunjung publik, pemohon tiket, maupun staf biasa tanpa izin dilarang keras membaca log audit operasional.
8. **Pemisahan Antrian Worker M9 (Isolation of Queues)**:
   - Modul M9 memisahkan jalur pemrosesan (*queue*) untuk notifikasi, audit, dan pembuatan laporan/ekspor agar kegagalan atau kelambatan satu beban kerja (misal job ekspor data bervolume besar) tidak menghambat pengiriman notifikasi atau pencatatan audit intent.
9. **Aksesibilitas Penuh Keyboard & Focus Management (AC20)**:
   - Komponen UI dasbor, filter laporan rentang tanggal, modal konfirmasi ekspor CSV, tombol aksi revoke telegram binding, dan navigasi tabel audit wajib dapat dioperasikan penuh melalui navigasi keyboard:
     - `Tab` dan `Shift+Tab` berpindah antar-kontrol form dan tabel secara logis.
     - `Enter` atau `Space` mengeksekusi aksi tombol ekspor, revoke binding, dan tanda baca notifikasi.
     - `Escape` menutup modal dialog ekspor dan mengembalikan fokus ke pemicu awal.
     - Atribut ARIA yang valid disematkan: `role="dialog"`, `role="region"`, `aria-label`, dan indikator status fokus yang jelas (*focus ring* tampak).

### Langkah 2: Model Domain, DTO, Store & Pusat Notifikasi M9
1. **DTO Notifikasi & Delivery (`backend/internal/modules/m9/api/notification.go`)**:
   - Definisikan `NotificationItem` (`ID`, `Version`, `Title`, `CreatedAt`, `Read` bool, `ReadAt` *time.Time, `DeliveryState` string ['STORED'|'SINK_ACCEPTED'|'FAILED'|'DEAD_LETTER'], `TicketID` *string, `AttemptID` *string).

   - Definisikan `TelegramBindingItem` (`ID`, `Version`, `SubjectID`, `OrgID`, `MaskedChatRef`, `Channel`, `VerifiedAt`, `RevokedAt`).
2. **Logika Domain Notifikasi & Validasi Scope (`backend/internal/modules/m9/internal/domain/notification.go`)**:
   - Validasi binding Telegram:
     - `Channel` wajib bernilai `"SINK"`.
     - `VerificationCode` minimal 1 karakter, maksimal 128 karakter.
     - Penegakan Scope Aktor vs `ScopeOrgID`:
       - Aktor publik/tamu dilarang mengikatkan diri pada organisasi internal OPD non-publik.
       - Aktor staf wajib terdaftar aktif pada organisasi `ScopeOrgID` yang dituju.
       - Pelanggaran scope menghasilkan error terstruktur `web.Fail(400, "Scope organisasi tidak valid untuk aktor")` atau 403/422.
   - Fungsi Sensor Kredensial / Secret Masking:
     - `MaskSecret(raw string) string`: Menyembunyikan karakter rahasia, menyisakan prefix dan suffix aman (contoh: `"1234567890:ABCDE"` $\rightarrow$ `"1234****CDE"` atau `"TG-***"`).
3. **Penyimpanan Database Notifikasi (`backend/internal/modules/m9/internal/store/notification.go`)**:

Menegakkan filter kepemilikan mutlak `WHERE recipient_id = $recipient_id` dan cursor order `created_at DESC, id DESC`.
   - `MarkNotificationRead(ctx, id string, recipientID string, expectedVersion int64, reason string) error`: Validasi kepemilikan notifikasi oleh `recipientID`, proteksi konkurensi optimistik `expected_version`, memperbarui `read_at = now()`, `version = version + 1`, dan mencatat intent audit ke `notify_audit.audit_intents`.
   - `StoreTelegramBinding(ctx, subjectID, orgID, rawChatRef, channel string) (*TelegramBindingItem, error)`: Menyimpan data pengikatan baru ke `notify_audit.telegram_bindings`, dengan chat reference tersimpan aman/tersensor pada proyeksi.
   - `RevokeTelegramBinding(ctx, id, subjectID string, expectedVersion int64, reason string) error`: Validasi kepemilikan binding, menetapkan `revoked_at = now()`, menaikkan versi, dan mencatat audit intent.

### Langkah 3: Pengikatan Telegram Terverifikasi & Sensor Kredensial (AC21)
1. **Handler Endpoint Telegram Binding**:
   - Implementasikan handler `POST /api/v1/notifications/telegram-bindings`:
     - Memeriksa otentikasi sesi aktor dan izin `notification.binding`.
     - Memvalidasi payload JSON `TelegramBinding`.
     - Menguji apakah `scope_org_id` sesuai dengan wewenang aktor. Jika tidak sah (misal aktor tamu mencoba mengikat chat ID internal), tolak dengan HTTP 400/422/403.

2. **Kueri Agregasi Laporan (`backend/internal/modules/m9/internal/store/report.go`)**:

   - Mengambil metrik sesi pengunjung dari `notify_audit.visitor_aggregates` untuk periode yang diminta.
   - Menghitung rasio kepatuhan SLA: `denominator` = total tiket diselesaikan dalam periode, `count` = jumlah tiket yang selesai sebelum batas SLA (*on-track*).
   - Memastikan tiket berstatus *breached* tetap dihitung di denominator dan tidak disembunyikan.
3. **Engine Ekspor CSV/JSON & Sanitasi Formula**:
   - Buat fungsi sanitasi formula CSV:
     ```go
     func SanitizeCSVField(val string) string {
         if len(val) > 0 && (val[0] == '=' || val[0] == '+' || val[0] == '-' || val[0] == '@' || val[0] == '\t' || val[0] == '\r') {
             return "'" + val
         }
         return val
     }
     ```
   - Handler `POST /api/v1/reports/exports`:
     - Memeriksa izin aktor: wajib memiliki `report.export`.
     - Validasi rentang waktu `from` dan `to` (RFC 3339 UTC).
     - Menyimpan job ekspor ke `notify_audit.export_jobs` dengan state `SUCCEEDED` (eksekusi langsung di lingkungan M0) dan menetapkan masa berlaku `expires_at = now() + 24 * time.Hour`.
     - Mengembalikan respons HTTP 202 Accepted dengan payload `Operation`.
   - Handler `GET /api/v1/reports/exports/{id}/download`:
     - **Dynamic Revocation Live Check**: Memvalidasi ulang sesi aktor dan izin `report.export` secara langsung. Jika sesi telah logout atau izin dicabut, tolak seketika dengan HTTP 401/403.
     - Menyajikan payload file CSV/JSON tersanitasi dengan header:
       - `Content-Type: text/csv; charset=utf-8` (atau `application/json`)
       - `Content-Disposition: attachment; filename="report-export-...csv"`
4. **Pembuktian Pencabutan Hak Dinamis (AC23 Dynamic Revocation Gate)**:
   - Skenario A: Aktor berizin `report.export` (misal AUDITOR atau COORDINATOR) mengajukan ekspor dan mengunduh berkas $\rightarrow$ berhasil (HTTP 202, lalu download HTTP 200).
   - Skenario B: Sesi aktor di-logout atau hak `report.export` dicabut, kemudian aktor mencoba mengunduh endpoint download yang sama $\rightarrow$ **seketika ditolak (HTTP 401/403)**, tidak ada baris atau cuplikan data yang terkirim.
   - Skenario C: Aktor tanpa hak `report.read` mencoba mengakses `GET /api/v1/reports` $\rightarrow$ ditolak tegas HTTP 403 Forbidden.

## 6. Larangan Keras & Guardrails Khusus

1. **Dilarang Mengirim Notifikasi Eksternal Nyata**: Modul M9 dilarang membuka koneksi HTTP ke server Telegram Bot API resmi (`api.telegram.org`) atau server SMTP internet nyata. Semua pengiriman wajib melalui sink deterministik terisolasi (`channel = 'SINK'`).
2. **Dilarang Menghubungkan Lintas Modul dengan JOIN SQL**: Modul M9 memiliki schema dan database pool tersendiri. Dilarang melakukan SQL JOIN langsung dari `notify_audit` ke schema `intake`, `identity`, atau `catalog`.
3. **Dilarang Membocorkan Secret Token Mentah pada Log / Respon (AC21)**: Token bot Telegram, kode OTP/verifikasi, dan nomor identitas pribadi dilarang muncul dalam bentuk mentah pada respon HTTP, pesan error, audit trail, maupun stdout/stderr.
4. **Dilarang Menyajikan File Ekspor Paska-Revocation (AC23)**: Jangan pernah mengandalkan link download statis tanpa otorisasi runtime. Setiap request download berkas wajib memverifikasi ulang sesi aktor aktif.
5. **Dilarang Menghasilkan File CSV Tanpa Sanitasi Formula**: Seluruh sel teks pada ekspor CSV yang diawali karakter formula (`=`, `+`, `-`, `@`) wajib diprefix tanda kutip tunggal `'` untuk mencegah eksekusi formula berbahaya pada aplikasi spreadsheet.
6. **Dilarang Mengubah Assertion Tes Agar Lulus Semu**: Jika terjadi kegagalan pada pengujian integrasi atau smoke test, perbaiki akar masalah pada implementasi modul, bukan melonggarkan batas pengujian.
7. **Dilarang Merangking Teknisi Secara Naif**: Laporan kinerja tidak boleh menyajikan peringkat teknisi hanya berdasarkan volume tiket selesai tanpa denominator dan konteks durasi yang jujur.
8. **Dilarang Menyebut Agregat Sesi Pengunjung Sebagai Warga Unik**: Statistik portal dari tabel `visitor_aggregates` wajib disajikan sebagai jumlah sesi pengunjung, bukan jumlah warga unik.
