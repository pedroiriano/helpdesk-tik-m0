## 2. Invariants Arsitektur, Keamanan & Ketahanan M0 yang Mutlak Dipatuhi

1. **Satu Proses Go & Sembilan Schema PostgreSQL Terpisah (The Monolith Invariant)**:
   - Tetap satu binary Go modular monolith dan satu instance PostgreSQL dengan sembilan database role/pool terisolasi (maksimal 4 koneksi per owner, total budget 36 koneksi).
   - Dilarang membuat microservices terpisah, dilarang HTTP loopback palsu antar-modul, dan dilarang membuat *shared business service* atau *shared repository* yang mengaburkan batas domain antar-modul.
   - Dilarang keras melakukan JOIN lintas skema antar-owner di database, foreign key lintas-owner, atau transaksi lintas-owner. Komunikasi antar-modul internal hanya melalui public Go interfaces dengan DTO/value semantics dan event outbox/inbox durable.
2. **Composition Root, Startup & Health Probes**:
   - `main.go` memuat konfigurasi dari environment/file, memvalidasi integritas `configs/M0.json` (memastikan tepat 9 modul terdaftar tanpa duplikasi atau modul asing), menginisialisasi 9 connection pools PostgreSQL, mengikat outbox delivery worker, dan mendaftarkan HTTP handler.
   - **Pemisahan Migrasi Database**: Migrasi DDL dijalankan melalui job/entrypoint terpisah (`infra/postgres/migrate.sh`) sebelum aplikasi berjalan; aplikasi Go dilarang keras menjalankan `CREATE TABLE` atau migrasi otomatis secara diam-diam saat startup/restart.
   - **Readiness vs Liveness**:
     - Readiness (`/readyz` atau handler readiness): memverifikasi ketersediaan koneksi ke 9 schema pool dan memeriksa kecocokan foundation marker serta domain marker. Jika versi skema tidak cocok, readiness **WAJIB GAGAL (HTTP 503)** dan menolak lalu lintas masuk.
     - Liveness (`/livez`): memverifikasi proses Go hidup dan responsif tanpa membebani database.
   - **Startup Failure Safety**: Kredensial tidak valid atau kegagalan koneksi database wajib menyebabkan startup berhenti (*fail-fast*) dengan pesan kesalahan yang aman dan teredaksi (tanpa membocorkan password).
3. **Penghentian Anggun (Graceful Shutdown Invariant)**:
   - Saat menerima sinyal `SIGINT` atau `SIGTERM`, runtime aplikasi wajib:
     1. Berhenti menerima koneksi/request HTTP baru.
     2. Memberikan tenggat waktu (*grace period / deadline*, default 10–15 detik) untuk menyelesaikan request in-flight yang sedang diproses.
     3. Menghentikan background delivery workers (outbox/inbox processor dan scheduler) secara kooperatif setelah menyelesaikan batch aktif saat ini.
     4. Menutup seluruh sembilan pool koneksi database PostgreSQL secara bersih.
   - Seluruh pekerjaan outbox/inbox yang belum di-ACK wajib tersimpan secara durable dan aman untuk diproses kembali (*resumed*) saat aplikasi dinyalakan ulang (*restart*).
4. **Alur Hidup Tiket Lengkap & Invariants Bisnis (End-to-End Integrity)**:
   - Modul M3 (`intake`) adalah **SATU-SATUNYA PENULIS STATE TIKET**. Modul lain dilarang memutasi state tiket secara langsung.
   - **Tamu**: Tiket tamu wajib dibuat dengan capability token berkekuatan kriptografis (Web Crypto / crypto/rand, bukan nomor tiket tebakan), dengan rate limit dan proteksi bot.
   - **Unggahan & Karantina**: Seluruh lampiran privat tiket wajib melalui pemindaian antivirus ClamAV; berkas `QUARANTINED` diblokir mutlak dari penyajian; lampiran privat dilarang keras di-reuse langsung ke publik tanpa salinan tersanitasi ber-provenance resmi (AC07, AC18).
   - **Verifikasi & Dispatch**: Guard `TICKET_NOT_VERIFIED` wajib memblokir dispatch tiket sebelum status `VERIFIED`; override klasifikasi otomatis M4 oleh operator wajib mencantumkan alasan bermakna ($\ge 5$ karakter); penugasan teknisi berjenjang L1/L2 M5 wajib tervalidasi ke staf aktif M1; mutasi bersaing wajib dilindungi CAS concurrency guard (HTTP 409 Conflict) (AC04, AC13).
   - **SLA & Resolusi**: Engine SLA M6 memproyeksikan kalender kerja CAL-1 vs CAL-247 (gross vs net); pencatatan vendor wajib memiliki PIC internal aktif dan jeda SLA terdeduplikasi (AC16); resolusi teknisi menetapkan batas konfirmasi pemohon 24 jam kalender; penolakan pemohon (`REJECT`) beralasan wajib melanjutkan episode awal ke `IN_PROGRESS`; job auto-close 24 jam kalender wajib membuktikan bukti notifikasi durable (`NotificationStored`) dan lolos dari race condition attempt CAS (AC05, AC08, AC14, AC15).
   - **Handoff Lintas OPD**: Pemindahan kepemilikan tiket antar-OPD diajukan `PENDING` dan saat `ACCEPT` memindahkan kepemilikan, regu penangan, dan mencabut delegasi teknisi lama secara atomik, dengan penegakan isolasi hak akses data pasca-handoff (AC06, AC17).
   - **Portal & Pencarian**: Editorial konten M8 tersanitasi server-side anti-XSS (AC12); rute menu navigasi M2 tidak pernah memberikan hak implisit (AC24); pencarian lintas-owner berizin M2/M3/M8 bebas bocoran catatan internal dengan penegakan *Dynamic Revocation Gate* paska-logout (AC23).
   - **Notifikasi & Audit**: Pengikatan Telegram ber-scope ketat dengan sensor rahasia kredensial (`TG-***`) dan pelacakan kegagalan `DEAD_LETTER` transparan (AC21); analitik SLA berpenyebut jujur (*honest denominator*); ekspor CSV tersanitasi formula injection (`=,+,-,@`); jejak audit M9 kekal (*append-only*) hanya untuk peran `AUDITOR` (AC20, AC21, AC23).
   - **Administrasi & Pemulihan**: Mode pemeliharaan `READ_ONLY` memblokir mutasi tulis (503) sambil mengizinkan baca (200); scoped runner allowlist menolak eksekusi shell bebas (400); permintaan purge non-Super Admin ditolak (403); permintaan purge Super Admin berstatus `DISABLED` (*pending formal retention policy*, zero data loss); penegakan kontrol ganda (*dual control*); pengarsipan tiket terminal dan pemulihan arsip aman (AC22, AC24).
5. **Observabilitas & Pembatasan Sumber Daya (Bounded Envelope)**:
   - Sumber daya runtime beroperasi dalam amplop yang ditentukan: CPU aplikasi 2500m / RAM 4608 MiB, PostgreSQL 1000m / 2560 MiB, Nginx 400m / 768 MiB (total envelope M0).
   - Concurrency worker, kapasitas antrean, batas ukuran payload (maks 10 MiB upload), batas waktu request (timeout), dan pool koneksi DB berukuran bounded dan terdefinisi eksplisit.
   - Metrik operasional mencakup latency request, error rate, statistik DB pool (idle/active/waits), lag antrean outbox/inbox, dan scheduler lateness.
   - **Kardinalitas Label Metrik Terbatas**: Label metrik **DILARANG MENGANDUNG** ticket ID, UUID acak, nama pemohon, atau PII dengan kardinalitas tak terbatas. Tracing mengkorelasikan correlation ID tanpa membocorkan payload rahasia.
6. **Aksesibilitas UI WAI-ARIA & Keyboard (AC20)**:
   - Seluruh halaman web publik (PIUI Modern) dan admin (PIUI Zero) wajib dapat dioperasikan secara penuh melalui keyboard (navigasi `Tab`, `Arrow keys`, `Enter`, `Escape`), fokus terlihat jelas (*focus ring*), atribut WAI-ARIA valid, modal dialog dilengkapi *focus trap* dan pengembalian fokus, serta kompatibel pada viewport desktop maupun mobile.
7. **Pemisahan Tegas Batas M0 dan Batas M0-13**:
   - Seluruh kriteria penerimaan AC01–AC25 disahkan untuk **cakupan M0**.
   - Aspek perbandingan empiris multi-model (C3 microservices, F9 serverless, G-OPT optimizer) dinyatakan secara jujur dan transparan sebagai **`DEFERRED_RESEARCH`** tanpa memalsukan benchmark atau angka coverage.
   - **Batas M0-13**: Penerimaan domain UAT manusia bersama pemilik proses (*human process owners*) dan keputusan otorisasi rilis produksi adalah ranah eksklusif **M0-13**. Kelulusan teknis (build PASS / test PASS) pada M0-12 **TIDAK MENGGANTIKAN** otorisasi rilis atau domain sign-off.

### Langkah 2: Pengujian Startup, Readiness, Liveness, dan Graceful Shutdown (`scripts/test_m0_12_shutdown.py`)

     - Mengirim request HTTP panjang yang sedang berjalan (*in-flight request*).

     - Memverifikasi bahwa port baru menolak koneksi masuk baru.
     - Memverifikasi bahwa in-flight request yang sedang berjalan berhasil diselesaikan secara tuntas sebelum shutdown berakhir (tidak terpotong mendadak).
     - Memverifikasi bahwa background delivery worker berhenti secara kooperatif tanpa meninggalkan outbox event dalam keadaan korup (*poisoned*).
     - Memverifikasi bahwa seluruh koneksi ke 9 pool database ditutup secara bersih (*clean pool close*).
     - Menyalakan ulang (*restart*) aplikasi dan memverifikasi bahwa outbox delivery worker melanjutkan pemrosesan event yang tertunda dengan benar.
2. Catat bukti hasil pengujian pada `qa/m0-12/shutdown.json` berstatus `"PASS"`.
