## 2. Invariants Arsitektur & Keamanan M0 yang Mutlak Dipatuhi

1. **Satu Proses Go & Sembilan Schema PostgreSQL Terpisah**:
   - Tetap satu binary Go modular monolith dan satu instance PostgreSQL dengan sembilan database role/pool terisolasi (maksimal 4 koneksi per owner, total budget 36).
   - Dilarang membuat microservices terpisah, dilarang HTTP loopback palsu antar-modul, dan dilarang membuat *shared business service* atau *shared repository* yang mengaburkan batas domain M1/M3/M9.
   - Dilarang keras melakukan JOIN lintas skema antara `identity`, `intake`, `knowledge`, dan `notify_audit`.
2. **Penolakan Mutlak Permintaan Purge oleh Non-Super-Admin (AC22)**:
   - Aktor dengan peran selain `SUPER_ADMIN` (seperti `PUBLIC`, `ASN`, `STAFF`, `OPERATOR`, `COORDINATOR`, `ADMIN_OPD`, maupun `PLATFORM_ADMIN`) yang mencoba meminta penghapusan permanen / purge data tiket (`POST /api/v1/admin/purge-requests` atau perintah sejenis) **WAJIB DITOLAK KERAS DENGAN HTTP 403 FORBIDDEN**.
   - Tidak ada kueri `DELETE FROM intake.tickets` umum pada API publik maupun admin. Riwayat tiket yang telah selesai atau dibatalkan hanya dapat diarsipkan, bukan dihapus.
3. **Workflow Purge Super Admin & Proteksi "Disabled Pending Policy" (AC22)**:
   - Pengajuan purge oleh Super Admin (`POST /api/v1/admin/purge-requests`) wajib dicatat pada `identity.system_operation_requests` dengan `kind = 'PURGE_REQUEST'`.
   - Karena kebijakan retensi legal dan regulasi pemusnahan data organisasi Kota Depok belum difinalisasi secara formal (`"purge_enabled": false` pada `contracts/policy/permissions.v1.json`), eksekusi fisik purge **WAJIB DINONAKTIFKAN SECARA DEFAULT**.
   - Status request operasi purge wajib berstatus `DISABLED` atau `PENDING` dengan alasan eksplisit bahwa kebijakan organisasi masih ditahan (*held pending formal retention policy*), membuktikan bahwa data tidak dapat dihapus sembarangan bahkan oleh Super Admin sebelum adanya regulasi resmi.
4. **Penegakan Kontrol Ganda / Dual Control pada Operasi Kritis (AC22)**:
   - Pada `identity.system_operation_requests`, penegakan integritas database `CHECK(approved_by IS NULL OR approved_by <> requested_by)` wajib ditaati: **Aktor yang mengajukan permohonan operasi kritis DILARANG KERAS menyetujui permintaannya sendiri**.
   - Persetujuan operasi kritis memerlukan subjek persetujuan yang berbeda (*two-man rule / dual-control*).
5. **Pengarsipan Tiket Berhistori Kekal & Pemulihan Arsip Aman (AC22)**:
   - Aksi pengarsipan tiket `POST /api/v1/tickets/{id}/archive` mewajibkan izin `ticket.archive` (dimiliki oleh `COORDINATOR`, `ADMIN_OPD`, `SUPER_ADMIN`).
   - Tiket hanya dapat diarsipkan jika sudah mencapai status terminal (`CLOSED` atau `CANCELLED`). Tiket yang masih aktif (`OPEN`, `TRIAGED`, `ASSIGNED`, `IN_PROGRESS`, `RESOLVED`) **DILARANG DIARSIPKAN** (HTTP 409 / 422).
   - Pengarsipan mencatat waktu `archived_at = now()` secara atomik, mempertahankan seluruh riwayat histori, catatan teknisi, komentar, dan lampiran tanpa ada data yang hilang.
   - Pemulihan arsip `POST /api/v1/tickets/{id}/restore-archive` mengembalikan tiket terarsip (`archived_at = NULL`) setelah memverifikasi integritas referensi dan keaktifan layanan terkait.
6. **Scoped Operational Runner Allowlist & Larangan Shell Bebas (AC24)**:
   - Endpoint eksekusi pekerjaan sistem `POST /api/v1/admin/operations` (`RequestSystemJob`) mewajibkan izin `system.job` (peran `PLATFORM_ADMIN`, `SUPER_ADMIN`).
   - Sistem **HANYA MENERIMA JOB KIND DARI ALLOWLIST RESMI**:
     1. `BACKUP_MANIFEST`: Pembuatan manifest backup metadata sistem dan katalog hash.
     2. `HEALTH_REPORT`: Evaluasi diagnosa kesehatan teredaksi seluruh modul M1–M9.
     3. `PURGE_REQUEST`: Pengajuan permintaan pemusnahan data terkendali (tunduk pada aturan invariant 3 & 4).
   - Segala bentuk permohonan dengan `kind` di luar allowlist **WAJIB DITOLAK SEGERA (HTTP 400 / 422)**.
   - Menegakkan invariant **AC24**: Aplikasi **DILARANG KERAS** menyediakan runner shell arbitrer, endpoint `exec`, pembukaan socket Docker langsung, atau konsol SQL interaktif bagi pengguna atau admin.
7. **Kebijakan Pemeliharaan Sistem (Maintenance Mode Policies)**:
   - Konfigurasi pemeliharaan `POST /api/v1/admin/maintenance` (`ConfigureMaintenance`) mewajibkan izin `system.maintenance` (peran `PLATFORM_ADMIN`, `SUPER_ADMIN`).
   - Mendukung dua mode pemeliharaan:
     - `READ_ONLY`: Seluruh permintaan mutasi tulis (`POST`, `PUT`, `PATCH`, `DELETE`) pada lingkup terdampak (organisasi tertentu atau global) seketika ditolak dengan respons HTTP `503 Service Unavailable` atau `423 Locked` beserta pesan informatif `message`, sedangkan permintaan baca (`GET`) tetap dilayani.
     - `DRAIN`: Mencegah penerimaan tiket atau registrasi pengguna baru, namun tetap mengizinkan pemrosesan tiket yang sedang berjalan oleh staf/teknisi hingga jendela pemeliharaan tiba.
   - Validasi ketat rentang waktu: `CHECK(ends_at > starts_at)`.
8. **Pemeriksaan Kesehatan Sistem Teredaksi (Redacted Health Check)**:
   - Endpoint `GET /api/v1/admin/health` (`ReadRedactedHealth`) mewajibkan izin `system.health` (peran `SUPER_ADMIN`, `PLATFORM_ADMIN`, `AUDITOR`).
   - Menyajikan status kesehatan seluruh 9 modul (M1–M9), ketersediaan scanner ClamAV, ketersediaan volume private uploads, serta metrik lag outbox/inbox.
   - **Penyensoran Informasi Sensitif**: Dilarang keras menampilkan connection string PostgreSQL, password, token API, secret key sesi, path direktori absolut host, atau kunci enkripsi pada respons health. Seluruh kredensial wajib diredaksi murni.
9. **Jejak Audit Kekal (Append-Only Audit Trail) pada M9**:
   - Setiap mutasi administrasi sistem (`ConfigureMaintenance`, `RequestSystemJob`, `ArchiveTicket`, `RestoreTicketArchive`, `RequestPurge`) **WAJIB MENERBITKAN INTENT AUDIT SECARA ATOMIK** dan dikonsumsi ke `notify_audit.audit_entries`.
   - Data audit bersifat kekal (*append-only*); tidak ada opsi pengubahan atau penghapusan audit.
10. **Dril Pemulihan Terisolasi Tanpa Efek Samping (Isolated Restore Drill)**:
    - Pengujian prosedur pemulihan basis data (*backup restore drill*) dilakukan menggunakan skrip otomasi pada instance basis data terpisah / skema temporer terisolasi.
    - Prosedur dril membuktikan kemampuan pemulihan data dari backup dump, memverifikasi konsistensi baris dan checksum ledger, serta menghitung estimasi RTO (*Recovery Time Objective*) dan RPO (*Recovery Point Objective*), **TANPA PERNAH MERUSAK ATAU MENGGANGGU BASIS DATA KERJA**.
11. **Aksesibilitas Navigasi Keyboard WAI-ARIA (AC20)**:
    - Seluruh antarmuka admin pemeliharaan, dialog konfirmasi eksekusi system job, dan kontrol arsip tiket pada PIUI Zero wajib dapat dioperasikan penuh melalui keyboard (`Tab`, `Shift+Tab`, `Enter`, `Escape`), dilengkapi focus trap pada modal dialog, penutupan `Escape`, dan pengembalian fokus ke pemicu awal.
