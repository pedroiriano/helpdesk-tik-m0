# ADR 0006 — Kredensial, scope dan persetujuan media RM0-01

10 November 2026. Keputusan implementasi lab lokal dalam scope RM0-01. Keputusan domain/SSO/produksi pada `planning/decisions.csv` tetap OPEN.

Autentikasi akun menerima email ternormalisasi atau NIK terdaftar dengan password. UUID, alias role dan NIP tidak menjadi pengganti bukti password. Pemilih subjek lab adalah jalur berbeda: konfigurasi lab loopback, key yang sah, ID fixture allowlist dan flag fixture aktif harus cocok. Endpoint autentikasi/registrasi dinonaktifkan pada mode non-lab sampai provider nyata disahkan. Validasi NIK hanya format, bukan verifikasi Dukcapil; UI menyatakan batas ini.

Password baru menggunakan PBKDF2-HMAC-SHA256 stdlib Go, 600.000 iterasi, salt acak 16 byte, verifier 32 byte dan format berversi. Tidak ada dependency baru. Verifikasi membatasi biaya/input dan membandingkan hasil secara konstan. Registrasi menerima 8–1024 byte, tanpa memangkas password. Referensi parameter: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html); API: [Go crypto/pbkdf2](https://pkg.go.dev/crypto/pbkdf2). Hash cepat historis diberi penanda legacy oleh migrasi 019. Hanya pembuktian password lama yang benar memicu upgrade dengan salt baru; password pengguna tidak diganti. Pemulihan kredensial nyata memerlukan proses terotorisasi, belum diaktifkan.

Registrasi memakai target dan scope intent deterministik berbasis HMAC serta uniqueness database untuk NIK/email. Receipt dan mutation payload tidak menyimpan password/token mentah. Replay memeriksa sesi/akun terkini dan tidak menghidupkan sesi revoked/expired. Database error dipropagasikan. Origin/CSRF dan cookie tetap diberlakukan pada mutasi.

Grant organisasi dibawa sebagai actor snapshot server sampai service/store. Hak di organisasi A tidak digabung dengan membership tanpa hak di B. M3 memakai predicate visibility tiket yang sama untuk pustaka lampiran dan search; konfigurator tidak otomatis membaca tiket. M8 memfilter konten/media sebelum LIMIT. M9 memeriksa scope organisasi job pada metadata/link/file ekspor setiap kali diambil. Hak reviewer approval diperiksa ulang melalui public port M1.

Unggahan M8 baru selalu PRIVATE, terikat principal dan satu organisasi berizin media.write. Claim versi/lease mencegah dua upload mengisi metadata yang sama. File memakai UUID staging baru, O_EXCL, ukuran bounded, pemeriksaan signature/hash/size dan scan ClamAV. Scanner gagal tetap quarantine. CLEAN hanya dapat diulang dengan byte yang sama. Bila commit tidak pasti, blob dipertahankan; collector volume bersama menunggu 24 jam dan memeriksa referensi M3 serta public port M8 sebelum menghapus orphan. Tidak ada SQL lintas owner. Semua referensi yang masih ada dipertahankan, termasuk quarantine yang perlu retry.

Sanitasi otomatis tidak diklaim. Pengunggah menyiapkan berkas hasil redaksi terpisah dan CLEAN dengan checksum berbeda. Untuk sumber M8, penerbit dengan content.publish pada organisasi tujuan meninjau sumber/salinan; untuk sumber tiket M3, peninjau harus sudah berhak membaca sumber melalui port M3 dan mempunyai ticket.read serta media.reuse pada organisasi yang sama. Ini memakai grant yang ada, tanpa menambah hak membaca tiket bagi editor/publisher. Reviewer berbeda dari pengunggah salinan. Publikasi konten tetap memerlukan content.publish.

Approval server mengikat owner/ID/version/hash sumber, ID/version/hash salinan, organisasi, target, audience, reviewer, alasan dan TTL 24 jam. Revoke sebelum pemakaian dan CAS/receipt tersedia. Reuse hanya menautkan salinan yang ditinjau ke konten M8; bukan menyalin byte sumber. Media tetap PRIVATE secara metadata dan akses pembaca mengikuti referensi konten PUBLISHED, audience dan organisasi. Archive konten menghapus akses publik pada request berikut. Approval yang sudah dipakai tidak dicabut retroaktif dengan menghapus audit; tarik publikasi melalui archive konten. Source/copy/target berubah, approval expired/revoked/palsu atau mandat reviewer dicabut ditolak.

Migrasi 019–020 additive; migrasi 001–018 tidak diubah. Media historis tanpa organisasi yang dahulu otomatis PUBLIC menjadi PRIVATE sambil mempertahankan blob, principal dan referensi. Pemilik masih dapat membaca; resume upload mengikat organisasi hanya dengan mandat media.write aktif yang tidak ambigu. Tidak ada publikasi kembali massal atau inferensi approval historis. Reuse tujuan M3 tidak pernah mempunyai implementasi penulisan tiket yang sah; kontrak kini membatasi target M8. Unggahan/lampiran tiket tetap melalui writer M3.

Tidak mengaktifkan model C3/F9/G-OPT, SSO/kanal nyata, purge atau deployment produksi. Hasil teknis, UAT manusia dan otorisasi rilis dicatat terpisah.
